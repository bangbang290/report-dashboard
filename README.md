# 국장님 보고 진행현황 (Streamlit 버전)

노션 "국장님 보고 진행현황" 데이터베이스를 대체하는 스트림릿 앱입니다.
노션과 달리 **본인이 등록한 항목만 수정/삭제**할 수 있고, 관리자 계정은 전체를 관리할 수 있습니다.
데이터는 노션 API 연동 없이 이 폴더 안의 SQLite 파일(`report_dashboard.db`) 하나로 저장됩니다.

## 화면 구성

| 화면 | 파일 | 설명 |
|---|---|---|
| 실시간 현황 (첫 화면) | `app.py` | "시작 전 / 진행 중"만 예정 시각 순으로 보여주는 요약 화면. 다들 상시로 띄워놓는 용도 |
| 보고 진행현황 | `pages/1_📋_보고_진행현황.py` | 등록 + 3개 탭(오늘 일정 3분할 / 예약 현황 / 전체 이력) |
| 월간 일정 | `pages/2_📅_월간_일정.py` | 국장님 월간 일정을 노션처럼 달력(캘린더) 형태로 등록/조회/수정/삭제 |
| 활동 이력 (관리자 전용) | `pages/3_🗂️_활동_이력.py` | 누가 언제 무엇을 등록/수정/삭제했는지 로그 |
| 사용자 관리 (관리자 전용) | `pages/4_👥_사용자_관리.py` | 관리자 승격/강등, 비밀번호 초기화 |

## 보고 등록 방식 (이번에 바뀐 부분)

- **과 / 팀 분리**: 등록할 때 "과"는 드롭다운에서 고르고(관세청 심사국 조직 기준으로 미리 넣어둠, 목록에 없으면 "기타(직접입력)" 선택), "팀 / 보고자"는 직접 타이핑합니다. 두 값을 합쳐서 화면에 표시됩니다 (예: "심사3관 11팀").
- **상태 자동 전환**: 등록할 때 상태를 사람이 고르지 않습니다. 등록하면 자동으로 **"시작 전"**, 예정 시각이 되면 자동으로 **"진행 중"**, 그로부터 **20분이 지나면 자동으로 "완료"**로 넘어갑니다. (화면을 열 때마다 현재 시각 기준으로 다시 계산합니다. 관리자가 예외적으로 상태를 앞당겨둔 경우는 자동으로 뒤로 되돌리지 않습니다.)
- **보고 예정 시각**: 09:30~18:00 사이에서 **10분 간격 드롭다운**으로 고릅니다 (타이핑 안 해도 됨). 날짜를 먼저 고르면 그 날짜에 이미 예약된 시간들을 바로 아래에 미리 보여줘서, 등록/수정하기 전에 겹치는지 미리 확인할 수 있습니다. (옛날 노션 데이터처럼 10분 단위가 아닌 시각이 이미 저장돼있는 항목을 수정할 때는, 그 시각도 목록에 임시로 끼워서 보여줍니다.)
- **보고 진행현황 페이지가 3개 탭으로 나뉩니다**:
  - **📍 오늘 일정**: 오늘 날짜 항목만, "진행 전 / 진행 중 / 완료" 3칸으로 나눠서 보여줍니다.
  - **🗓️ 예약 현황 (오늘 이후)**: 오늘보다 뒤 날짜로 등록된 예약들을 시간순으로 보여줍니다.
  - **🗃️ 전체 이력**: 기존처럼 검색/필터 가능한 전체 목록 (과거 이력 포함).

## 1. 최초 설치

```bash
pip install -r requirements.txt
```

## 2. 기존 노션 데이터 가져오기 (최초 1회만)

노션 Export zip을 압축 해제한 폴더를 넣어서 실행하면, 기존 이력 데이터를 그대로 옮겨옵니다.

```bash
python migrate_notion.py "노션_export_압축푼_폴더_경로"
```

- `보고 진행현황 ..._all.csv` → `reports` 테이블로 이관
- `국장님 월간 일정 ..._all.csv` → `monthly_schedule` 테이블로 이관
- 옮겨온 항목의 등록자는 `노션가져오기`로 표시됩니다. 이후 **관리자 계정**으로 로그인하면 이 항목들도 자유롭게 수정/삭제할 수 있습니다.
- 이미 실행한 뒤 다시 실행하면 중복으로 쌓입니다. 재실행이 필요하면 `report_dashboard.db` 파일을 지우고 다시 실행해주세요.

## 3. 실행

```bash
streamlit run app.py
```

## 4. 계정 만들기 / 로그인

- 최초 접속 시 "최초 등록" 탭에서 이름 + **PIN(숫자 4자리)**으로 계정을 만듭니다.
- **가장 먼저 가입하는 사람**에게만 "관리자 계정으로 등록" 체크박스가 보입니다. 관리팀(비서실 등) 담당자가 제일 먼저 가입하면서 체크하는 것을 추천합니다. 이후에는 관리자 화면(👥 사용자 관리)에서 다른 사람을 관리자로 승격/강등할 수 있습니다.
- 일반 사용자는 본인이 등록한 항목만 수정/삭제 가능, 관리자는 전체 항목을 수정/삭제할 수 있습니다.
- 로그인은 새로고침하거나 브라우저를 다시 열어도 최대 30일간 유지됩니다(쿠키 기반). 로그아웃 버튼을 누르면 즉시 풀립니다.
- PIN을 5회 연속 틀리면 5분간 로그인이 잠깁니다 (무차별 대입 공격 방지 — 4자리 숫자는 조합이 10,000개뿐이라 이 잠금장치가 특히 중요합니다).

## 5. 관리자 전용 화면

| 화면 | 설명 |
|---|---|
| 🗂️ 활동 이력 | 누가 언제 무엇을 등록/수정/삭제했는지 전체 로그 조회 |
| 👥 사용자 관리 | 사용자를 관리자로 승격/강등, PIN 초기화(임시 PIN 발급) |

두 화면 모두 관리자 계정으로 로그인해야만 보입니다. 관리자가 아닌 계정으로 접속하면 "관리자만 볼 수 있습니다" 안내만 뜹니다.

### 관리자 계정, 이렇게 관리하시는 걸 추천드려요

- **관리자를 최소 2명은 유지해주세요.** (예: 비서실 담당자 + 다른 한 명) 관리자가 1명뿐이면, 그 사람이 PIN을 잊거나 자리를 비웠을 때 아무도 관리자 화면에 못 들어가는 상황이 생깁니다. 지금은 관리자가 1명뿐일 때 "사용자 관리" 화면에 경고 문구가 뜨도록 만들어뒀습니다.
- **최악의 경우(관리자 전원이 PIN을 잊음)를 위해 `emergency_admin_tool.py`를 같이 넣어드렸습니다.** 앱에 로그인하지 않고도, 이 폴더가 있는 PC에서 직접 명령어로 관리자를 새로 지정하거나 PIN을 초기화할 수 있는 비상용 도구입니다. IT담당자나 비서실처럼 서버 PC에 물리적으로 접근 가능한 사람만 쓸 수 있으니, 신뢰할 수 있는 사람만 알고 있게 해주세요.
  ```bash
  python emergency_admin_tool.py list                      # 전체 사용자/역할 확인
  python emergency_admin_tool.py promote 홍길동              # 홍길동을 관리자로 승격
  python emergency_admin_tool.py reset-pin 홍길동 1234       # 홍길동 PIN을 1234로 강제 초기화
  ```

## 6. 스트림릿 커뮤니티 클라우드 + Turso로 배포하기 (외부망/핸드폰용)

관세청 예산 지원 없이도 **무료로** 인터넷/핸드폰에서 쓸 수 있게 배포하는 방법입니다.
스트림릿 커뮤니티 클라우드는 코드를 재배포하거나 앱이 오래 안 쓰이면 로컬 파일이 초기화될 수 있어서,
데이터 저장소만 Turso(무료 지속형 DB)로 바꿔서 데이터가 절대 사라지지 않게 만들어뒀습니다.

> ⚠️ Turso 연동 부분은 이 코드를 만든 환경에 네트워크가 막혀 있어서 실제 서버에 붙여서 테스트는 못 해봤습니다.
> 아래 순서대로 하시다가 안 되는 부분 있으면 그대로 알려주세요, 같이 고치겠습니다.

### 6-1. Turso 데이터베이스 만들기

1. [turso.tech](https://turso.tech) 에서 무료 계정을 만듭니다.
2. 대시보드에서 새 데이터베이스를 하나 만듭니다 (이름은 아무거나, 예: `report-dashboard`).
3. 만들어진 DB의 **연결 URL**(`libsql://xxxx.turso.io` 형태)과 **Auth Token**(인증 토큰)을 발급받아 둡니다. (대시보드에 "Create Token" 같은 버튼이 있습니다.)

### 6-2. GitHub에 코드 올리기

1. GitHub에 새 저장소(레포지토리)를 하나 만듭니다 (Private으로 만들어도 됩니다).
2. 이 `report_dashboard` 폴더 전체를 그 저장소에 올립니다 (GitHub 웹사이트에서 파일 드래그해서 업로드하셔도 되고, `git` 명령어를 쓰셔도 됩니다).
   - `report_dashboard.db` 파일이 있다면 **올리지 않는 게 좋습니다** (Turso를 쓰면 이 로컬 파일은 더 이상 안 쓰입니다). `.gitignore` 파일에 `report_dashboard.db*` 한 줄 추가해두면 실수로 안 올라갑니다.

### 6-3. 스트림릿 커뮤니티 클라우드에 배포

1. [share.streamlit.io](https://share.streamlit.io) 에 GitHub 계정으로 로그인합니다.
2. "New app" → 방금 올린 저장소 선택 → Main file path에 `app.py` 입력 → Deploy 클릭.
3. 배포되면 `https://무언가.streamlit.app` 형태의 주소가 생깁니다. 이 주소가 바로 핸드폰/PC 어디서든 접속하는 주소입니다.

### 6-4. Turso 접속 정보를 스트림릿 시크릿에 등록

1. 배포된 앱 관리 화면에서 "Settings" → "Secrets" 메뉴로 들어갑니다.
2. 아래처럼 입력하고 저장합니다 (6-1에서 발급받은 값으로 바꿔서):
   ```toml
   TURSO_DATABASE_URL = "libsql://xxxx.turso.io"
   TURSO_AUTH_TOKEN = "여기에_발급받은_토큰"
   ```
3. 저장하면 앱이 자동으로 재시작되면서, 이제부터는 로컬 파일 대신 Turso에 데이터를 저장합니다.

### 6-5. (선택) 기존 노션 데이터를 Turso로 바로 이관

내 PC 터미널에서 아래처럼 환경변수를 걸어주고 마이그레이션 스크립트를 실행하면, 로컬이 아니라 바로 Turso로 데이터가 들어갑니다.

```bash
export TURSO_DATABASE_URL="libsql://xxxx.turso.io"
export TURSO_AUTH_TOKEN="여기에_발급받은_토큰"
python migrate_notion.py "노션_export_압축푼_폴더_경로"
```

(Windows 명령 프롬프트라면 `export` 대신 `set` 을 쓰시면 됩니다.)

### 6-6. 직원들에게 안내

전에 관세조사 앱 안내하셨던 것처럼, `https://무언가.streamlit.app` 주소 하나만 공유하시면 됩니다. 핸드폰은 그 주소를 브라우저 즐겨찾기나 홈 화면에 추가해두면 앱처럼 쓸 수 있습니다.

## 7. (참고) 내부망 배포 방식 — 나중에 필요해지면

혹시 나중에 마음이 바뀌어서 내부망에도 같이 두고 싶으시면 이 방법도 그대로 살아있습니다.

1. 내부망 PC 한 대에서 이 폴더를 그대로 둔 채 `streamlit run app.py` 를 실행합니다. (Turso 시크릿을 설정 안 했다면 자동으로 로컬 `report_dashboard.db` 파일을 씁니다.)
2. 실행하면 터미널에 `Network URL: http://<사내IP>:8501` 같은 주소가 뜹니다. 이 주소를 팀원들에게 공유하면 각자 브라우저에서 접속할 수 있습니다.
3. PC가 꺼지거나 터미널이 종료되면 접속이 끊기므로, 상시 운영하려면 그 PC를 계속 켜두거나(또는 백그라운드 실행) 필요합니다.
4. 방화벽에서 8501 포트가 내부망 다른 PC들에게 열려 있어야 합니다.

> 오늘 만든 "관세조사 계획보고서 자동화" 프로젝트의 `내부망_배포_가이드.md`가 있다면 그 문서의 상세 절차를 그대로 재사용하시면 됩니다 (배포 방식 자체는 동일).

## 8. 보고 시간 등록 규칙

- **순서 = 등록한 시각이 아니라 "예정 보고 시각" 기준**입니다. 10시 예약자가 먼저 등록했더라도, 나중에 9시로 등록하는 사람이 있으면 그 사람이 목록에서 더 앞에 옵니다.
- **20분 간격 자동 체크**: 같은 날짜에 이미 등록된 보고 시간과 20분 미만으로 겹치게 등록/수정하려 하면 자동으로 막고, 겹치지 않는 가장 빠른 시간을 추천해줍니다. (예: 9:10에 이미 예약이 있는데 9:15로 등록하려 하면 → "9:30 이후로 등록해주세요"라고 안내)
- 정말 예외적으로 간격을 무시하고 등록해야 하는 경우를 위해, 등록/수정 폼에 "⚠️ 20분 간격 무시하고 그래도 등록" 체크박스를 넣어뒀습니다. 필요 없다면 안내 문구만 보고 그냥 쓰시면 됩니다.
- **동시 등록 충돌 방지**: 두 사람이 정확히 같은 순간에 같은 시간대를 등록하려 해도, DB 차원에서 한 명씩 순서대로만 처리되도록 만들어져 있어 한쪽만 성공하고 다른 쪽은 자동으로 충돌 안내를 받습니다. (실제로 10명이 동시에 같은 시간을 등록 시도하는 테스트로 검증했습니다.)

## 9. 알아두면 좋은 것들

- 예정일이 파싱되지 않는 원본 데이터(예: 시간 형식이 특이하거나 값이 비어있던 항목)는 `scheduled_date`가 비어있는 채로 들어옵니다. 실시간 현황에는 뜨지만 정렬은 맨 뒤로 갑니다 — 필요하면 "보고 진행현황" 화면에서 수정해서 날짜를 채워주세요.
- DB 백업은 `report_dashboard.db` 파일 하나만 복사하면 됩니다. (WAL 모드라서 `report_dashboard.db-wal`, `report_dashboard.db-shm` 파일이 같이 생길 수 있는데, 백업 전에 앱을 완전히 종료하면 이 파일들이 자동으로 본 파일에 합쳐집니다.)
- 실시간 현황 화면 좌측의 "자동 새로고침(30초)" 토글은 기본이 꺼짐 상태입니다. 계속 띄워놓는 모니터 화면이라면 켜두시면 됩니다. (화면이 멈추지 않는 가벼운 타이머 컴포넌트를 사용합니다.)
- 등록/수정/삭제/역할변경/비밀번호초기화는 전부 "활동 이력" 화면에 자동으로 기록됩니다.
- 삭제 버튼은 바로 지워지지 않고, "정말 삭제하시겠습니까?" 확인을 한 번 더 거칩니다.

## 10. 알려진 한계 / 설치 후 확인해보시면 좋은 것

- **Turso 연동은 실제 서버로 검증하지 못했습니다** (위 6번 참고). 저장소 연결(`_TursoConn`/`_TursoCursor` 어댑터) 부분이 이번 배포에서 가장 위험 부담이 큰 부분이니, 배포하시고 안 되는 부분 있으면 바로 알려주세요.
- **로그인 유지(쿠키) 기능은 `extra-streamlit-components`, 캘린더 화면은 `streamlit-calendar`라는 외부 라이브러리를 씁니다.** 둘 다 실제 브라우저 환경(로컬 PC)에서 `streamlit run`으로 띄워야 정상 동작을 확인할 수 있는데, 이 세션에서는 네트워크가 막혀 있어 패키지를 설치해서 브라우저로 직접 띄워보지는 못했습니다. DB/로직 쪽 핵심 기능(동시성, 충돌체크, 자동 상태 전환, 권한, 이력)은 전부 파이썬 코드로 직접 실행해서 검증했지만, 이 두 컴포넌트가 실제 브라우저에서 매끄럽게 동작하는지는 처음 실행하실 때 한 번 확인해봐 주세요.
  - 로그인 유지가 잘 안 되면(새로고침해도 계속 로그인 창이 뜨면) 말씀해주세요.
  - 캘린더에서 일정 클릭이 잘 안 먹으면, 그 아래 "🗒️ 전체 목록으로 보기/수정"을 펼치면 예전 방식(목록+버튼)으로 똑같이 수정/삭제할 수 있습니다.
- 관리자가 0명이 되는 상황(마지막 관리자를 강등)은 코드로 막아뒀지만, DB 파일을 직접 건드려서 관리자를 전부 지우는 경우까지는 막을 수 없습니다. (그런 경우엔 `emergency_admin_tool.py` 로 복구하시면 됩니다 — 단, Turso를 쓰는 경우엔 이 도구를 실행하는 PC에도 `TURSO_DATABASE_URL`/`TURSO_AUTH_TOKEN` 환경변수를 걸어줘야 원격 DB에 접근합니다.)
- PIN은 SHA-256 해시로 저장됩니다 (평문 저장 아님). **다만 외부 인터넷에 공개하는 만큼, 4자리 숫자보다 더 긴 비밀번호로 바꾸는 걸 실제 운영 전에 권장드립니다.**
